# 月度排班表导出设计

## 目标

为门店排班系统增加 Web 端导出月度排班表的能力。店长和店员都可以将当前门店、指定月份的已保存排班下载为 Excel 文件，文件包含适合打印和离线查看的月度总表，以及解释班次颜色和时间的班次说明。

## 已确认范围

- 导出格式仅为 Excel `.xlsx`，本次不提供 PDF 或 CSV。
- 仅实现 Web 端入口，不修改微信小程序的用户界面。
- 店长和店员均可导出当前门店的全店月排班。
- 导出范围与当前排班页一致：包含所有在职员工，包含店长行；不提供员工筛选、个人视图或工时统计。
- 导出月份使用排班页当前选中的月份。
- 店长存在未保存草稿时，必须先保存修改，导出按钮不发起请求。
- 导出只读取数据库中已经保存的数据，不把浏览器草稿写入文件。
- 不新增导出历史记录，也不在服务器磁盘落地临时文件。

## 方案

由 Go 后端生成 Excel，Web 前端只负责发起经过认证的下载请求并保存二进制响应。

新增只读接口：

```text
GET /api/schedules/export?month=YYYY-MM
```

接口复用现有认证中间件，不限制角色。认证后使用 JWT 中的 `storeId` 查询数据，不能通过请求参数指定门店。后端在内存中生成完整工作簿，只有在生成成功后才设置下载响应头并写出内容，避免返回不完整的文件。

使用 `github.com/xuri/excelize/v2 v2.8.1` 生成标准 `.xlsx` 文件。该版本支持项目现有的 Go 1.24.1 基线；依赖加入 `apps/server/go.mod`，并由 Go module 锁定。

## 数据流

1. 用户在排班页选择月份。
2. Web 端点击“导出 Excel”。
3. 如果店长的 `drafts` 非空，前端提示“请先保存修改后再导出”并结束流程。
4. 前端调用 `GET /api/schedules/export?month=<month>`，请求携带现有 JWT，响应类型为 `blob`。
5. 后端认证用户、校验月份格式，按 `storeId` 查询门店、在职用户、班次模板和月份内排班。
6. 后端生成工作簿并以附件响应。
7. 前端从 `Content-Disposition` 读取文件名；如果没有可解析的文件名，则使用 `<YYYY-MM>-排班表.xlsx` 回退名称，创建对象 URL，触发浏览器下载，随后释放对象 URL。
8. 下载结束后清除加载状态；失败时解析 JSON 或 Blob 形式的错误消息并显示 Element Plus 错误提示。

## 后端接口行为

### 请求

```text
GET /api/schedules/export?month=2026-08
Authorization: Bearer <JWT>
```

`month` 必须通过现有 `monthRange` 校验，格式为真实有效的 `YYYY-MM`，拒绝年份 `0000` 和不存在月份。

### 成功响应

```text
200 OK
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="2026-08-schedule.xlsx"; filename*=UTF-8''<url-encoded-file-name>
Cache-Control: no-store
```

实际文件名使用清理后的门店名称、中文月份和“排班表”组成，例如：

```text
示例门店-2026年08月排班表.xlsx
```

文件名中的路径分隔符、控制字符和其他不适合作为文件名的字符必须替换或移除，同时保留稳定的 ASCII 回退名。

### 错误响应

- 未携带或无法验证 JWT：`401`，沿用现有 JSON 错误结构。
- 首次登录尚未改密：`403`，沿用现有认证中间件行为。
- `month` 缺失、格式错误或不是有效月份：`400`。
- 数据库或工作簿生成失败：沿用现有内部错误 JSON 响应。

无排班记录不是错误。此时仍生成包含在职员工和日期表头的空月度总表，空单元格显示 `-`。

## Excel 工作簿

### 工作表一：`月度排班表`

- 第一行合并从 A1 到最后日期列，显示 `<门店名> <YYYY年MM月> 排班表`。
- 第二行是表头：`员工`、`角色`，之后按月份日期升序排列。
- 日期表头显示日期日号和星期，例如 `01\n周三`。
- 每个在职员工一行，排序与现有 `GET /api/users` 一致：角色升序、姓名升序。
- 角色显示为“店长”或“店员”。
- 有排班的单元格显示班次名称；没有排班显示 `-`。
- 班次单元格尽量使用班次配置颜色作为背景色，文字使用适合背景的白色；无效颜色降级为中性灰色，不导致整个导出失败。
- 周末日期列使用浅色表头和浅色背景区分。
- 所有数据单元格使用边框和居中对齐；员工和角色列保持左对齐或适合阅读的对齐方式。
- 冻结前两行和前两列，使横向滚动时仍能看到员工和角色，纵向滚动时仍能看到标题和表头。
- 设置适合横向打印的页面方向、页宽适配和重复表头；这些设置失败不能改变数据导出结果。

### 工作表二：`班次说明`

- 按班次模板的 `sortOrder`、创建时间顺序排列。
- 列出：班次名称、班次编码、开始时间、结束时间、类型、颜色。
- `isOff=true` 时类型显示“休息”，时间显示“休息”；其他班次类型显示“上班”。
- 颜色列显示原始颜色文本，并使用规范化后的颜色填充示例单元格。
- 保留表头样式、边框、适度列宽和冻结首行。

### 数据一致性

导出查询必须分别限制 `storeId`，并只查询 `isActive = 1` 的用户。排班通过用户和班次的门店条件关联，避免跨门店数据混入。排班状态、备注和版本号不在本次文件中单独导出，因为当前排班页的可见内容是员工、日期和班次。

## Web 端交互

修改 `apps/web/src/views/ScheduleView.vue`：

- 在现有刷新按钮附近增加带下载图标的“导出 Excel”按钮。
- 店长和店员都显示该按钮。
- 增加独立的导出加载状态，导出期间禁用按钮并显示加载态。
- 店长有草稿时先提示保存；不自动保存、不覆盖草稿、不请求后端。
- 使用当前 `monthValue`，月份切换后立即按新月份导出。

修改 `apps/web/src/api/index.ts` 增加导出 API 类型封装，修改 `apps/web/src/api/http.ts` 使 Blob 错误响应能够读取现有 JSON 错误消息；成功响应保持 Blob，不影响现有 JSON API。

## 安全与错误边界

- 下载接口必须挂在 `s.authenticate` 下，不能创建未鉴权的文件生成路径。
- 不接受用户 ID、门店 ID 或班次 ID 作为导出范围参数。
- 文件生成完全在内存中完成，响应前不创建公共临时文件。
- 文件名清理后不得允许路径穿越或控制字符注入响应头。
- 前端对象 URL 必须在下载触发后释放。
- 后端发生错误且响应头尚未写出时，返回统一 JSON 错误；不要在已写入 Excel 响应后再追加 JSON。

## 测试策略

### Go 集成测试

在现有 `server_test.go` 中增加测试覆盖：

- 店长成功下载当前月份，验证状态码、Excel Content-Type、Content-Disposition 和非空响应体。
- 店员成功下载同一月份，验证导出路由不是店长专属。
- 未认证请求返回 `401`。
- 非法月份返回 `400`。
- 生成的工作簿可被 `excelize` 重新打开，包含 `月度排班表` 和 `班次说明` 两张表，且包含月份表头、seed 员工、排班班次和班次说明内容。
- 创建另一门店的员工和排班后，验证当前门店导出不包含另一门店数据。
- 修改为无排班月份后，验证仍能打开文件并包含表头结构。

### Web 验证

- 执行 `npm run build -w @shift/web`。
- 手工验证店长有草稿时不会请求导出接口。
- 手工验证店长和店员分别可以下载文件，下载文件可由 Excel 或兼容阅读器打开。
- 手工验证服务端错误能在页面显示，而不是触发损坏文件下载。

## 非目标

- 不支持 PDF、CSV、微信小程序导出。
- 不增加员工筛选、个人排班导出、工时统计、加班统计或排班审批历史。
- 不改变现有排班保存、发布、实时同步和数据清理逻辑。
- 不引入异步导出任务、导出历史或云端文件存储。
